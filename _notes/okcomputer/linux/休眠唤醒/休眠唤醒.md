Linux中的休眠唤醒是通过 /sys/power/state 来操作的。

目前Linux支持四种睡眠深度：

- PM_SUSPEND_TO_IDLE	freeze	最浅的睡眠，仅把进程暂停？
- PM_SUSPEND_STANDBY	standby	？
- PM_SUSPEND_MEM	进程与设备的状态保存到内存中
- PM_SUSPEND_MAX	进程与设备状态保存到硬盘中，会进入冬眠路径（hibernate）

针对s2ram分析，即PM_SUSPEND_MEM。

休眠流程
========

Linux的系统休眠分为以下几个阶段，定义在enum suspend_stat_step中：
- SUSPEND_WORKING
- SUSPEND_FREEZE
- SUSPEND_PREPARE
- SUSPEND_SUSPEND
- SUSPEND_SUSPEND_LATE
- SUSPEND_SUSPEND_NOIRQ
- SUSPEND_RESUME_NOIRQ
- SUSPEND_RESUME_EARLY
- SUSPEND_RESUME

软件状态的休眠（enter_state()）
-------------------------------

操作sysfs后，进入kernel/power/main.c中的处理函数，先解析入参，并调用
kernel/power/suspend.c中的enter_state()开始处理。

enter_state() 的大致流程如下：
1. 先尝试获取system_transition_mutex，这个锁定义在kernel/reboot.c中，看起来是
   控制整个系统状态的锁。
   如果获取失败，则直接返回，宣告进入休眠失败。
2. 根据sync_on_suspend_enabled的配置，选择是否完成FS的同步。这个配置是.config中
   的静态配置，在编译时就需要完成选择。
3. 把pm_suspend_global_flags清零，后续用于记录休眠过程中的状态。
4. suspend_prepare
   4.1 冻结FS
   4.2 冻结进程
   __此时系统已经进入SUSPEND_FREEZE状态__
5. 冻结设备

设备休眠以后就会进入整系统休眠的状态，但从代码来看，进入此函数以后，直到wakeup，
都不会返回：

```c
//...
	error = suspend_devices_and_enter(state);

Finish:
	events_check_enabled = false;
	pm_pr_dbg("Finishing wakeup.\n");
	suspend_finish();    // 此处已经在恢复进程和fs
Unlock:
	mutex_unlock(&system_transition_mutex);
	return error;
```

存在两个疑点：
1. 是否真的进入suspend_devices_and_enter()函数就是进入了休眠?
2. 执行软件侧的休眠时，为什么是先冻结FS再冻结进程？

设备的休眠（suspend_devices_and_enter()）
-----------------------------------------

设备的休眠主要由suspend_devices_and_enter()函数实现，执行流程如下：
1. 校验并调用平台的回调函数（platform_suspend_begin()），当前arm/arm64的实现是
   通过psci固件回调完成
2. 调用dpm_suspend_start()函数，让设备进入休眠
3. 进入一个suspend的循环，直到wakeup命令发出

其中dpm_suspend_start()定义在drivers/base/power/main.c中，是管理所有设备的休眠唤
醒的核心机制。

dpm的全称（应该）是device_power_management，通过几个链表来管理需要由PM子系统管理
的所有设备：

```c
LIST_HEAD(dpm_list)	// 正常的尚未进入休眠状态的所有设备
static LIST_HEAD(dpm_prepared_list)
static LIST_HEAD(dpm_suspend_list)
static LIST_HEAD(dpm_late_early_list)
static LIST_HEAD(dpm_noirq_list)
```

设备初始化过程中会调用device_pm_add()函数来把自己添加到dpm_list中，这是定义在
drivers/base/core.c:device_add()的标准动作。

dpm_suspend_start()函数进入休眠的过程，就是一步步调用回调，把dpm_list中的
设备转移到dpm_suspend_list中的过程。

过程大体如下：

1. 调用prepare回调（dpm_prepare()）先flush所有正在进行的驱动加载，并禁用新的驱动
   加载把执行完毕的驱动添加到dpm_prepared_list。

   >在这一步之前的进程或其他软件状态进入休眠失败不再会影响后续的设备休眠，内核
   > 会把失败的调用通过dpm_save_failed_step()记录在suspend_stats中。
   > 
   >此处记录的失败并不会详细记录失败的具体的函数、设备或错误码等，而仅会记录错
   > 误发生的阶段。

3. 调用suspend回调（dpm_suspend()），把执行完毕的驱动添加到dpm_suspend_list
   此处会实际调用驱动的suspend()函数。

   内核默认suspend()函数耗时较久，因此会以prepare完成的顺序反向遍历设备，通过
   workqueue异步调用没有子设备的叶子设备的suspend()函数。

   在异步调用中没有遍历到的设备（父设备等）或由于异步任务已满导致未被调度的
   设备，会在之后的while循环中完成调用。

   > 子设备与父设备的概念？

   while循环中的逻辑也是尽可能使用异步任务完成suspend函数的调用。

   > 在这一步出现的失败，会导致整个suspend失败，内核会回滚之前的软件、arch的
   > 休眠。


上述异步调用suspend()函数中，对于单个设备的休眠是如何调用的？

不同的设备可能同时存在多种角色，例如一个设备可能既是平台设备，也接入了某个总线。
如果总线设备和平台设备都实现了suspend()函数，同时这个设备驱动本身也实现了
suspend()函数，那么应该调用哪个？

Linux中的代码实现如下：

```c
   if (dev->pm_domain) {
           info = "power domain ";
           callback = pm_op(&dev->pm_domain->ops, state);
           goto Run;

   if (dev->type && dev->type->pm) {
           info = "type ";
           callback = pm_op(dev->type->pm, state);
           goto Run;
  
   if (dev->class && dev->class->pm) {
           info = "class ";
           callback = pm_op(dev->class->pm, state);
           goto Run;

   if (dev->bus) {
           if (dev->bus->pm) {
                   info = "bus ";
                   callback = pm_op(dev->bus->pm, state);
           } else if (dev->bus->suspend) {
                   pm_dev_dbg(dev, state, "legacy bus ");
                   error = legacy_suspend(dev, state>bus->suspend,
                                           "legacy bus ");
                   goto End;
           }

Run:us

   if (!callback && dev->driver && dev->driver->pm) {
           info = "driver ";
           callback = pm_op(dev->driver->pm, state);

   error = dpm_run_callback(callback, dev, state, info);
 
```

也就是Linux会依次调用
- pm_domain
- type
- class
- bus
的回调，调用完相应的回调以后，再调用设备自己的suspend()

当设备自身的suspend()回调正常返回后，会取消置位父设备以及此设备的supplier的相应
flag，这样来允许后续父设备和supplier的suspend，从而保证下电顺序正常。


PM_DOMAIN
---------

pm_domain是为了让相同设备实现不同的拓扑以及掉电顺序与规则设计的。
